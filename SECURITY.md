# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.2.x   | :white_check_mark: |
| < 0.2   | :x:                |

## Reporting a Vulnerability

We take the security of Hermes seriously.

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, please report them privately by one of the following methods:

- Open a private security advisory on GitHub:  
  [https://github.com/ryomenhaider/Hermes/security/advisories/new](https://github.com/ryomenhaider/Hermes/security/advisories/new)
- Or contact the maintainer directly via GitHub (@ryomenhaider)

### What to include in your report

- Description of the vulnerability
- Steps to reproduce
- Affected version(s)
- Potential impact
- Any proof-of-concept (if available)

### What to expect

- We will acknowledge receipt of your report within **72 hours**
- We will investigate and keep you updated on the progress
- Once the issue is resolved, we will publicly credit you (unless you prefer to remain anonymous)

## Security Best Practices for Users

- Always keep Hermes and its dependencies up to date
- Never commit API keys, tokens, or secrets to the repository
- Use environment variables or a secrets manager for credentials
- Prefer the latest stable release

Thank you for helping keep Hermes and its users safe.
